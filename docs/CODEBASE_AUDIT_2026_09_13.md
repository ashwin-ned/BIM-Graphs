# RoboBIM codebase audit — 13 September 2026

> **Status of these findings, 14 September 2026.** A02 and A06–A12 are
> repaired; see the [M0 implementation record](M0_IMPLEMENTATION_2026_09_14.md).
> **A01, A03, A04 and A05 — the geometry findings — are not**, and
> `tests/test_m0_regressions.py` asserts that each still reproduces exactly as
> described below, so a fix makes its case fail rather than leaving a stale
> expectation. The "what the current results establish" table below was written
> against the pre-repair scorers and stands as a record of that state; current
> figures are in the M0 record.

The code is a useful research prototype for recovering room connectivity from IFC. It is not yet a dependable building prior for robot autonomy. The most consequential weaknesses are the geometry-to-topology contract, preservation of uncertainty, and the connection between annotation and evaluation. Adding a larger LLM before repairing these would make it harder to tell whether richer outputs are more correct.

This audit precedes the proposed [pipeline redesign](PIPELINE_REDESIGN_2026_09_13.md). Production code, datasets, annotations, and existing experiment results were left unchanged. New diagnostic scripts and their outputs are under [audit_2026_09_13](audit_2026_09_13/).

**Scope and evidence**

I mapped the workspace, reviewed the first-party processing modules and their callers, examined annotation composition, persistence, rendering, exports and tests, inspected experiment and annotation artifacts, and read the local workshop manuscript and subsequent design documents. The first-party `main/` and `annotator/` source inventory contains 55 Python/JavaScript/HTML/CSS files and 15,546 lines, including tests and styles. The 25 corresponding source files in `ifc-graphx/annotator/` are duplicate copies in the audited snapshot. [Source hashes](audit_2026_09_13/source_manifest.json) identify the exact files inspected.

The workspace root has no Git repository. `ifc-graphx/` is a nested Git repository and was clean. There is no root package manifest or dependency lock. The available Conda Python works, while `python` and `node` are absent from the default shell PATH. Tests used the Python and Node binaries in `/mnt/data/home/anedung/miniforge3/envs/bim-sg/bin/`.

Third-party review covered Ifc2Graph's relevant geometry/adjacency implementation, its adapter, IFC2SB's build patches, and the recorded integration findings. It was not a line-by-line audit of the vendored IFC2SB C++ engine. The entire 208-model corpus and historical GPU experiments were not rerun. Findings below distinguish fresh reproductions, source inspection, and historical results.

**What is actually implemented**

| Area | Implementation and assessment |
|---|---|
| IFC ingestion | `main/bimsg/parser.py`: tessellation, mesh footprints, placement matrices, a subset of spatial relationships, empirical unit correction, furniture prototype reuse. Useful foundation, but most IFC properties and relational semantics are discarded. |
| Spatial reconstruction | `spaces.py`, `topology.py`: storey assignment, raster components, subtraction of stated spaces, proximity adjacency, door probing, gap detection, stair links. Main research contribution and main correctness risk. |
| Graph | `graph.py`: building → storey → space → element with several room-to-room relation types. Geometry remains in memory and is lost on serialization. |
| Robot queries | `navigation.py`, `qa.py`, `demo.py`: width/stair filters, centroid-based Dijkstra, regex question answering, basic storey summaries. No executed robot navigation or online belief update. |
| Semantics | `semantics.py`, `label_corpus.py`, `eval_semantics.py`, `eval_goal_resolution.py`: rules, text LLM and VLM room classification; stored predicted labels; conditional label masking. No current general affordance, hazard, operational-state, or functional-zone model. |
| Synthetic evaluation | `generate_building.py`, `damage_ifc.py`, `verify_gt.py`, `baselines.py`, `eval_connectivity.py`, `significance.py`: controlled IFC corruption and pair-level scoring. Valuable regression infrastructure with a narrow generative distribution. |
| Real-data evaluation | `audit_dataset.py`, `validate.py`, `derive_real_gt.py`, `eval_real_connectivity.py`, `evaluate.py`: schema statistics, plausibility checks, derived geometric reference, human verdict scoring. The human-data path is currently inconsistent. |
| Visualization | `render_floorplan.py`, `render_plan.py`, `export_plans.py`, `visualize.py`: several different geometry/rendering paths. Only `render_floorplan.py` performs actual triangle-plane intersection. |
| Annotation | Flask app, static browser app, server/localStorage/folder backends, Python/JS composers, GT collector, pin recovery, checklist, GraphML/GEXF/HTML exporters. Substantial reusable work, with critical semantic-contract defects. |
| Diagnostics and reports | `proxy_probe.py`, `verify_ramblr_report.py`, research TeX/PDFs, design documents, saved JSON reports. Useful historical evidence, sometimes written with conclusions stronger than the measurements support. |
| Orchestration | `run_pipeline.sh`, Pages workflow: experimental script and annotator deployment. No integrated ingestion-to-semantics-to-robot release process. |

The [ICRA 2026 manuscript](../icra_paper/RoboBIM_ICRA26_WS/conference_revised.tex) describes occupancy, waypoint and room graphs plus seven LLM stages and a topology regression gate. That implementation is not the current `main/` pipeline. The newer [ICRA 2027 draft](../icra_paper/RoboBIM_ICRA27_Paper/paper.tex) explicitly shifts toward correctness. Preserve this distinction when reporting reproducibility: the present source tree does not independently reproduce the workshop's seven-stage agent or its robot-facing export contract.

**Confirmed findings that should block new correctness claims**

Severity here means impact on the intended research and robot use. These are not claims of incidents on a deployed robot.

| ID | Finding | Evidence and consequence | Required correction |
|---|---|---|---|
| A01 | Room recovery does not take a horizontal section. | [`parser.py`](../main/bimsg/parser.py), `_footprint_from_mesh` and `parse`; [`spaces.py`](../main/bimsg/spaces.py), `infer_rooms_for_storey`. Most products get a convex hull of the entire XY projection. Testing `zmin <= slice <= zmax` only selects a product; it does not slice it. A reproduced wall with a lintel has an open doorway in the true section and a sealed doorway in the footprint. Concavities and slab voids can also be filled. | Use physical sections/height bands for reconstruction; preserve topology of polygons and holes. Promote and harden the existing section primitive from the renderer. |
| A02 | Multiple doors overwrite each other. | [`graph.py:126`](../main/bimsg/graph.py) uses the relation as the MultiDiGraph key. Two doors joining the same rooms leave one edge per direction. A 1.2 m door followed by a 0.4 m door makes a wheeled route disappear; reversing the input order restores it. Serializer/load also collapses independently keyed parallel edges. | Give every portal and edge a stable identity. Test route and serialization invariance under product reordering. |
| A03 | Door probing can connect through another wall. | [`topology.py:179`](../main/bimsg/topology.py) samples at 0.85, 1.35 and 1.95 m without checking the intervening segment. Reproduction: it skips a 0.5 m room and links the door to the room beyond a solid wall. | Associate portal sides with the immediately incident free-space regions, with host-wall and crossing checks. Unresolved incidence must remain unresolved. |
| A04 | Reported width is not physical clear width. | [`topology.py:253`](../main/bimsg/topology.py) uses the longest world-axis bounding-box side. A 1 m × 0.05 m door rotated 45° becomes 0.742 m. Stair `clear_width` is a bounding-box dimension of the core, not usable flight width. | Distinguish authored overall dimensions, geometric aperture dimensions, and usable clearance; use local portal coordinates and uncertainty. |
| A05 | A route can rest entirely on an unverified connection. | [`topology.py:436`](../main/bimsg/topology.py) connects vertically overlapping rooms named Stair without any stair solid. [`navigation.py:44`](../main/bimsg/navigation.py) accepts missing widths. The reproduction returns a legged route with no stair geometry and all connector metrics unknown. Door state, headroom, floor support and turning feasibility are not checked. | Separate candidate topology from verified feasibility; return feasible/infeasible/unknown and route preconditions. |
| A06 | “Unsure” rooms enter ground truth. | [`annotator/compose.py:102`](../annotator/compose.py) excludes `not_a_room` and unjudged rooms but retains `unsure`; JS does the same. A reproduction exports the unsure room and an accepted incident edge, sets `complete=true`, and leaves `held_out` empty. | Explicitly hold out uncertain rooms and affected relations. Keep review completion distinct from suitability for scoring. |
| A07 | Current annotation verdicts are ignored by the older scorer. | [`main/evaluate.py:37`](../main/evaluate.py) recognizes `correct`/`spurious`; current annotations use `real`/`not_a_room` and `passable`/`not_passable`. Two real rooms and one passable edge produce zero judged items. Its main connectivity score also omits the separate vertical verdict/addition collections. | Use a shared, versioned annotation schema and canonical verdict adapter; score horizontal and vertical relations explicitly. |
| A08 | Human GT export is incompatible with the advertised evaluator. | [`compose.py:231`](../annotator/compose.py) emits no `adjacent_not_connected`; [`eval_connectivity.py:97`](../main/eval_connectivity.py) requires it and raises `KeyError`. Further mismatches: GUID room identity versus synthetic room names, missing synthetic rectangle fields, different edge-type vocabulary, and annotator-suffixed filenames. Negative verdicts are dropped during composition and cannot be recovered from the positive-only export. | A single evaluation contract with explicit positive/negative/unknown scope, stable identities and a real-data adapter. Adding an empty negatives array alone does not fix this. |
| A09 | The derived real reference has additional unit and geometry defects. | [`derive_real_gt.py:157`](../main/derive_real_gt.py) scales tessellated metre coordinates by `model.unit_scale` again. Equivalent metre/mm opening fixtures produce 1 versus 0 accepted voids. `_clean` also uses the 0.5 m² room threshold for walls and voids: a normal 0.9 × 0.2 m doorway footprint is discarded. | Use only the empirical correction on already normalized mesh coordinates; separate class-specific validity criteria; rebuild reference artifacts. |
| A10 | Synthetic scoring can hide unsupported geometry. | [`eval_connectivity.py:38`](../main/eval_connectivity.py) omits edges touching unmatched nodes and permits many recovered nodes to map to one GT room by centroid. Reproduction: an extra invented room and edge do not add a false positive. The saved 150-building result rows report zero unmapped rooms, so this particular omission is a demonstrated harness vulnerability, not an established explanation of those saved scores. | Evaluate room instances with explicit matching, splits/merges and unmatched predictions, then score edges in that matched space. Retain a separate conditional topology track. |
| A11 | Semantic masking leaves upstream label information in features. | `topology.vertical_connections` uses Stair labels before [`eval_semantics.collect`](../main/eval_semantics.py) masks them. A masked room still has the vertical edge induced by its original label; `n_vertical` reaches the classifier. This is direct target-derived information for that class, in addition to the deliberate neighbor-label context. | Mask selected evidence before building any derived features. Separate input-available labels from held-out targets across the entire dependency graph. |
| A12 | VLM target lookup is ambiguous on this corpus. | [`render_plan.py`](../main/render_plan.py), `PlanCache.crop`, selects the first `Space.name == room_number`, without GUID/storey. Saved graphs have repeated stated room numbers in `model_6` and `model_17`. Later rooms with those numbers can receive another room's image. | Pass GlobalId and assert storey/geometry identity; re-evaluate images and text on a manifest of identical targets. |

Every reproduction above that uses a small fixture is available in [probes.py](audit_2026_09_13/probes.py), with [observed output](audit_2026_09_13/probe_results.json). Source-inspection limitations are called out rather than presented as measured corpus effects.

**Other material implementation problems**

- **Static publication loses available IFC files.** [`annotator/build_site.py`](../annotator/build_site.py) reuses `src` for an asset filename at line 59, then searches for IFC files below that filename at line 88. The fixture supplies an IFC beside a plan, yet the build omits it and reports `hasIfc=false`. The existing static test inserts an IFC and edits the manifest *after* building, so it does not test the broken copy step.
- **The schema baseline mistakes a shared wall for a door.** [`baselines.m_schema`](../main/baselines.py) groups every shared boundary element without checking its type. Two spaces bounded by a solid `IfcWall` produce `connected_by_door`. Zero-boundary inputs conceal this error. The production parser also ignores supplied space boundaries rather than benefiting from valid ones.
- **Storey membership is mistaken for geometric extent.** Graph recovery and both plan paths select products by one `storey_gid`. A wall assigned to the ground storey can extend through several storeys but is unavailable as a blocker above it. Authoring hierarchy and spatial intersection require separate indexes. Storey `Elevation` alone is also not a general replacement for the full placement chain.
- **Graph persistence drops the information needed for downstream validation.** Footprints, holes, meshes, effective units, frames, extraction configuration, confidence, and most graph-level metadata are absent from the saved graph. Renderers must reparse; the classifier/annotator then joins old predictions to freshly reconstructed identifiers without a source/configuration hash. Ifc2Graph adapter errors stored in `g.graph` are dropped by `to_json`.
- **IFC semantics are mostly unavailable to the LLM.** `Product.properties` is never populated. Types, property sets, quantities, materials, systems, zones, classifications, void/fill and door-operation relations are not collected into an evidence model. `IfcFurnishingElement` is parsed as clutter but absent from `KEEP_ELEMENTS`, as are some structural subtypes and ramps. A stronger model cannot recover facts removed upstream.
- **A geometric region is implicitly treated as one room and one navigable component.** Largest-component selection, slab convex hulls, the 2 m² cutoff, raster closing, and 0.25 m erosion remove or merge legitimate regions. A named architectural space may contain several disconnected navigable components; an open plan may have several functions with no wall between them.
- **Routing and QA overstate what they know.** `length_m` includes the 25 m-equivalent stair penalty and centroid distances, so it is not metric route length. `local_navmesh` is not connected to the planner and keeps only its largest component. Exact room references lose priority to taxonomy lookup: “Kitchen 2” returns both kitchens, and QA picks the first. QA route calls do not accept a robot profile. The LLM prompt describes retrieved facts as deterministic even when they include inference.
- **Semantic fallback is not fully observable.** The text model's six-token answer is coerced to a label or silently replaced by the rule. In the VLM, a truncated trace without `</think>` can still reach `_coerce`; a category mentioned in unfinished text may be taken as the answer despite a log message claiming prior fallback. Raw outputs, fallback reasons and truncation counts are not persisted in the evaluation record. `canonical('outdoor')` returns `None`; “Open Floor Plate” maps to outdoor despite recovery deliberately using that name for an interior unpartitioned floor. Zero elevation is treated as nonground by `(elevation or 1)`.
- **Annotation persistence needs revision awareness.** Browser `loadAnnotation` catches a failed read and resets to an empty annotation, enabling a later save to overwrite previous work. Server saves share a fixed `.tmp` filename per annotation, leaving a concurrent-writer race. These are source-inspected risks, not incidents reproduced on user data. Pin recovery appropriately emits proposals, but source copying between floors must remain a hypothesis; unresolved pins and merge/split requests cannot disappear from benchmark completeness.
- **The convenience runner is unsuitable for reproducible experiments.** [`run_pipeline.sh`](../run_pipeline.sh) removes synthetic inputs/results, uses a fixed interpreter path, lacks `set -e`/`pipefail`, suppresses failures, and can print DONE after a failed stage. It was intentionally not run during the audit. Missing outputs are skipped by scorers; there is no full manifest enforcing denominators. A missing model must count as a failed run, not disappear from evaluation.
- **Some visualization contracts still disagree.** The annotation exporter preserves room holes, while `render_floorplan.py` and `render_plan.py` export/draw only outer rings. SVG labels/title are interpolated without XML escaping. `visualize.py` draws raw inferred regions before the graph's stated-space subtraction, so its orange overlay is not the final graph partition. These can mislead manual diagnosis even when graph code is unchanged.

**Scientific interpretation that needs correction**

1. **A transition-count gate cannot guarantee topology correctness.** The workshop gate can preserve the number of edges while deleting a necessary edge and adding an impossible one. Adding edges can only help its count criterion, including edges through walls. A regression check needs evidence, identity and task-relevant connectivity, not a monotone edge count.
2. **Schema absence is corpus-specific evidence.** A missing space-boundary relationship does not mean IFC has no topology, nor that an arbitrary shared boundary permits walking. IFC has other useful relationships, including void/fill chains. The “98.5% functional labels” audit accepts any nongeneric name; it is not a semantic correctness audit. Only 593 saved stated rooms map into the current taxonomy.
3. **The synthetic generator makes the geometry problem unusually friendly.** Layouts are axis-aligned rectangular subdivisions; wall thickness, door sizes and storey height are fixed; openings are full-height gaps between wall pieces; stairs are solid boxes; slabs are not authored as realistic stair apertures. Door orientations explicitly match the inference assumption. This is useful controlled testing, not independent support for general physical traversability. The verifier shares the parser, checks horizontal pairs only, and cannot validate the staircase model.
4. **Strong F1 from an all-positive baseline does not make a benchmark unable to rank methods.** The real-reference documentation says such a baseline winning is a statement about the benchmark rather than the methods. That conclusion is too strong. On a trustworthy, representative distribution, its winning is evidence the method needs improvement. Report base rates, specificity/MCC, precision-recall and task cost; do not adjust sampling merely to make the proposed method win. A separate balanced diagnostic set is useful if clearly separated from deployment prevalence.
5. **Different algorithms over the same damaged geometry are not independent truth.** Slicing removes projection artifacts only where the underlying mesh contains an opening; it cannot recover a void absent from the model. Synthetic calibration is not a bound on real accuracy. `derive_real_gt.calibrate` also counts only reference-decided pairs, so it needs an explicit denominator for all target pairs and abstentions. Use this output as weak evidence or disagreement mining, not GT.
6. **The current evidence does not settle the value of vision.** The VLM receives an unlabeled IFC-derived crop with no independent plan text and a different feature package than the text LLM. Crop identity, truncation, model differences and sampling further confound the comparison. A low score here does not rule out OCR, legends, dimensions or symbols from external architectural drawings.
7. **Conditional label recovery is not autonomous goal execution.** Leave-one-room-out is useful but optimistic for whole missing storeys and clusters of recovered rooms. Rules were adjusted after inspecting corpus labels, without a protected building-level test split. The goal metric is candidate-set recall, largely classification accuracy in another form. Routes are checked only for resolved targets; the “entry” is the largest circulation room anywhere, not a validated entrance/start pose. Neither establishes arrival at the intended goal.
8. **An IFC prior is a prior about the physical building.** Accurate extraction of a modeled opening is not confirmation that the real door is open, unlocked, reachable or still present. A model-derived floor finish does not measure present friction or wetness. The representation must keep those distinctions available to the robot.

**What to preserve**

Keep the modular parser/recovery/graph separation; original IFC identities; placed geometry in metres; geometry reuse for repeated furniture; explicit relation types; robot constraints applied at query time; deterministic classification baseline; corruption generator; paired statistical machinery; annotation proposals and bulk flags; browser tests; and the growing record of failed hypotheses. These are substantial assets.

The first implementation step should repair the evaluation/serialization contracts and establish a versioned baseline. Then replace the footprint-based reconstruction with a geometry and portal layer. The [redesign](PIPELINE_REDESIGN_2026_09_13.md) specifies the LLM role, hierarchy, floorplan fusion, robot interface and experiments that should follow.
