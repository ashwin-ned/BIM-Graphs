# Code and design-logic audit — 18 September 2026

Run after P1 (vision modality) and the first half of P2 (label vocabulary,
`score_labels`). Every finding below was measured, not inferred; the commands are
given so each can be re-checked.

The headline is not a defect. It is that **a reference this project formally told
itself not to use has become usable**, and nobody re-measured it after the fix
that repaired it.

---

## B1 — The derived reference now supports real-corpus specificity

`docs/REAL_CORPUS_GT.md` carries a section titled "Why these numbers must not be
used", whose first and principal argument is:

> Across the 15 gated models there are **428 pairs where the pipeline found an
> actual `IfcDoor` joining two rooms and the reference calls them separated** --
> more than the 300 door-backed pairs it agrees with.

Recomputed against the reference now on disk:

| | doc (pre-rebuild) | measured today |
|---|---|---|
| door-backed pairs the reference agrees with | 300 | **362** |
| door-backed pairs called separated | **428** | **17** |

A 96% reduction. The doc's supporting table is stale in the same way: it reports
`model_6` with 93 doors and **0** voids and `model_16` with 38 and **0**; both now
carry 93/93 and 38/51, and **no model in the corpus has doors without voids**.
`docs/M0_IMPLEMENTATION_2026_09_14.md` records that `results/real_gt/` "had to be
rebuilt" — the rebuild fixed this and the conclusion drawn from the old data was
never revisited.

Consequence, measured by scoring `ours` against it through `evaluation/`:

```
OURS vs the annotation-free DERIVED reference — 17 gated models
  425 positives, 289 genuine negatives, 0 unknown
  precision 0.788   recall 0.904   F1 0.842   SPECIFICITY 0.644
  precision_strict 0.406   f1_strict 0.561
  out of scope 80   unmatched endpoint 378
```

**This is a real-corpus specificity, and there was supposed to be none.** It is
independent of the pipeline's proposals because the reference is a flood-fill,
not a correction of what the pipeline suggested — which is exactly the defect
that makes the annotated reference give specificity 0.000. The paper now has two
references that can discriminate: synthetic (specificity 0.993) and real
(0.644). The gap between them is a generalisation result worth reporting, not an
embarrassment.

Caveats that must travel with it: 17 of 25 models pass the trust gate, so this is
not the whole corpus; `precision_strict` 0.406 and 378 predictions on unmatched
endpoints say the pipeline asserts a great deal outside the reference's room set,
and that is charged honestly rather than hidden.

**Action:** `docs/REAL_CORPUS_GT.md` now carries a correction banner. Its
measurements are preserved as the record; its conclusion is superseded.

## B2 — A01 is a defect in the *reference*, not only in the method

The doc's stated cause for the unreliable negatives is worth quoting:

> Where a door has no authored void, the projected wall seals it, the reference
> says "separated", and a correct prediction is scored as a false positive.

That is open finding **A01** — "room recovery takes the XY projection, not a
section, so a lintel seals a doorway" — appearing inside the ground-truth
producer rather than the pipeline. `main/derive_real_gt.py` rasterises
projections and cuts only *authored* `IfcOpeningElement` voids; it does not take
a section.

So the A01 repair scheduled for P4 has a second payoff nobody has costed: the
same `_section_segments` primitive (already written and correct at
`main/render_floorplan.py:83-122`, used on real IFC at `:250`, and deliberately
unused by the topology path) would let the deriver stop depending on authored
voids at all. **Fixing A01 improves the method and the only independent real
reference in one change.** That raises its priority above A03/A04/A05.

## B3 — Room-level recall is 100% circular, worse than edge recall

Edge recall against the annotated reference is already known to be a
proposal-acceptance rate: all 7 false negatives are exactly the links the
annotator typed in by hand. Room recall is worse. Measured over the ten complete
buildings:

```
reference room provenance: {'ifc': 308, 'inferred': 67}
375 reference rooms; 0 came from an annotator rather than the pipeline
```

**The reference room set is the pipeline's room set.** Room recall against it is
1.000 by construction and cannot detect a missed room at any rate. The
missing-room pins that would fix this exist (2–14 per building, 45 on the
complete ten) but only 1 of 45 ever resolved into a node, for a mechanical
reason already diagnosed: `parser.py:28-32` puts `IfcStair`/`IfcSlab`/`IfcRoof`
in `OCCLUDING_TYPES`, `export_plans.py:115-124` dumps every occluding footprint
into `storey["walls"]`, and `resolve_pins.py:188` then treats them all as walls —
so 35 of 37 stair pins fail with "the pin sits inside a wall", blocked by the
very object that was pinned.

No room-level recall number should be quoted from the annotated reference. The
derived reference (B1) has an independently derived room set and does not share
this defect.

## B4 — Two label vocabularies, and five live call sites used the broken one — FIXED

`evaluation/labels.py` was added this session with the defects fixed, but
`main/bimsg/semantics.py` kept its own `TAXONOMY` and `canonical()`, and these
call sites still used it:

```
main/eval_goal_resolution.py:45      main/bimsg/qa.py:67, :70
main/eval_semantics.py:113           main/bimsg/semantics.py:163, :397, :412
```

So `Store Front → storage`, `W.C. (Women) → no match` and `Lab → no match` were
live in the semantic evaluation path while the fixed vocabulary sat beside it
unused. This is the hazard the project's own "`evaluation/` is the one scorer"
rule exists to prevent, and the reason `verdicts.py` has a triple-copy parity
assertion.

`semantics.py` now re-exports `TAXONOMY`, `CANON` and `canonical` from
`evaluation.labels`, so there is one vocabulary. `tests/test_labels.py` asserts
`CLASSES == semantics.CANON`, because the backends are told to predict into
`CANON` and a drift there asks a model for a label the scorer cannot score.

## B5 — `_coerce` still scores an unusable answer as the rule baseline — OPEN

`main/bimsg/semantics.py` (`_coerce`, formerly `:386-397`):

```python
    return canonical(t) or fallback      # fallback = the rule's own hypothesis
```

A model that emits nothing parseable is scored as if it had agreed with the
deterministic prior. The module's own comments record that this already made one
published "VLM accuracy" identical to the rule baseline. It is unchanged.

`evaluation.scoring.score_labels`, added this session, does the opposite: an
absent prediction is `pred_missing` and an unusable one is `pred_unmapped`, both
charged and reported separately. **The backends must be moved onto that
accounting before any model number is quoted**; this is the P2 item still open.

Measured now, honestly: `predicted_label` is null on all 303 scorable rooms of
the annotated corpus, so label accuracy is 0.000 — nothing has been predicted
since M0 rebuilt the graphs over `label_corpus.py`'s output.

## B6 — A tautology I introduced and caught in the same session

The first `score_labels` read `attrs.get("predicted_label") or attrs.get("label")`.
The fallback scores the IFC name against the IFC name, so a pipeline that
predicts nothing would have reported near-perfect accuracy — the identical shape
to the 380/380 edge-type figure (`compose.py:185` copies the pipeline's relation
into the reference and `scoring.py` compares it to itself). Removed, and
`tests/test_labels.py` now asserts that a graph with no `predicted_label` scores
0.000 rather than 1.000.

Worth recording because it is the third instance of this exact failure in the
project, and the first two shipped.

## B7 — The label denominator that was reported wrongly

An earlier audit put `canonical()` coverage at 66.9% and "2913 rooms silently
dropped". Re-measured: **79.5% (5025/6323)** before this session's fixes, **81.6%
after**, and **88.0% of rooms that carry a real name**. The 66.9% figure divided
by all 8792 rooms including 2469 `inferred` ones, which have no IFC label and
never could — a denominator that counts unlabellable rooms as coverage failures.

The genuine finding underneath it stands and was larger than reported in one
place: `main/generate_building.py:112` emits "Lab" as one of twelve synthetic room
types and no keyword matched it, so **166 of 2049 rooms in the primary corpus
(8.1%) were unscorable** — invisible because `canonical()` returned `None`
indistinguishably from an unnamed room. Now 0.

## B8 — The damage axis has two regimes, not four

Recorded in full in `docs/SYNTH_BENCHMARK_2026_09_18.md`. L2 and L3 produce
byte-identical graphs for `adjacency`, `door_near` and `ours`; only `ours` and
`adjacency` change at all at L4, and pooled metrics are identical to three
decimals across L2–L4. The files do differ (`IfcRelAggregates` 5→4→3,
`IfcRelContained` 2→0). Orphaning spaces from their storey is absorbed because
storey assignment is recovered geometrically; undeclared centimetres are absorbed
by `parser.detect_scale_correction`. A robustness result, but the paper must not
claim a four-level severity gradient.

## Still open from M0, unchanged

- **No split manifest.** A threshold tuned on a building can still be evaluated
  on it. Which buildings are development material is an untaken research
  decision, and four of the ten complete annotated buildings are provably
  debug material (model_2, 11, 16, 17, cited in source comments).
- **No schema validator** run on every output. The eleven invariants are checked
  on a fixture and by an ad-hoc sweep. Measured earlier: 0/25 graphs and 0/40
  ground-truth files violate any of them, so it will land green — it is
  insurance, not a bug hunt.
- A graph declaring `schema: 99` still scores F1 1.000, and an empty graph still
  records as `ok, complete: true, exit 0`. The manifest closed "file missing"
  and left "file present and wrong" one level down.

## What is healthy

Worth stating, because an audit that lists only faults misleads.

`evaluation/score_connectivity` is genuinely modality-agnostic — it never refers
to IFC or to how a prediction was produced, which is why a VLM's predicted graph
will score through the same path with no new scorer. The four-way precision split
charges a hallucinating method for inventing rooms. `RunManifest` fixes
denominators before scoring and refuses to let a failure leave silently. The
"`evaluation/` is the one scorer" rule is actually held: only the two documented
exceptions deviate. And `tests/test_m0_regressions.py` asserting that its own
four open defects still reproduce is an unusually strong reproducibility
position — a suite that fails when a known bug is fixed, on purpose, so the fix
arrives with a demand to update the record.
